#### Phase 1 — Guide pas à pas (pédagogique)

Voir le détail dans la conversation Cursor / commande `/as400-integration` — résumé des étapes ci-dessous.

**Avant de toucher au serveur** — demander à l'expert :
1. IP fixe de l'AS400 ? (→ whitelist UFW optionnelle)
2. Mot de passe ou clé SSH publique ?
3. Nom de fichier attendu côté stocks (ex. `stocks_YYYYMMDD_HH.csv`) ?

**Étape A — Groupe, dossiers, utilisateur** (sur le VPS, en `sudo`) :
```bash
# 1. Groupe dédié (obligatoire avant useradd)
sudo groupadd sftp-as400

# 2. Arborescence chroot
sudo mkdir -p /var/sftp/as400/{entrant,sortant}

# 3. Utilisateur sans shell, sans home auto (-M)
sudo useradd -g sftp-as400 -d /var/sftp/as400 -s /usr/sbin/nologin -M sftp-as400

# 4. Permissions chroot (règle OpenSSH : racine = root, 755)
sudo chown root:root /var/sftp/as400
sudo chmod 755 /var/sftp/as400

# 5. Sous-dossiers éditables par sftp-as400
sudo chown sftp-as400:sftp-as400 /var/sftp/as400/entrant /var/sftp/as400/sortant
sudo chmod 755 /var/sftp/as400/entrant /var/sftp/as400/sortant
```

**Étape B — SSH chroot** : fichier `/etc/ssh/sshd_config.d/sftp-as400.conf` :
```
Match User sftp-as400
    ChrootDirectory /var/sftp/as400
    ForceCommand internal-sftp
    AllowTcpForwarding no
    X11Forwarding no
    PasswordAuthentication yes
    KbdInteractiveAuthentication yes
    AuthenticationMethods password
```
> VPS durci : `PasswordAuthentication no` global — le bloc `Match` **autorise le mot de passe uniquement** pour `sftp-as400`. `deploy` reste en clé.

Puis : `sudo sshd -t` puis `sudo systemctl reload ssh`

Test Mac : `sftp -o PreferredAuthentications=password -o PubkeyAuthentication=no -P 22 sftp-as400@HOST`

**Étape C — Mot de passe** : `sudo passwd sftp-as400` (mot de passe long, noter dans gestionnaire de mots de passe — pas le vault git)

**Étape D — Test** depuis ta machine :
```bash
sftp -P 22 sftp-as400@152.228.218.35
# cd entrant → put test.txt → ls
```

**Étape E — Transmission** : envoyer [[Securite/as400-fiche-expert]] + mot de passe **à part** (pas dans le même mail que la fiche si possible).

## Spec sortant — Phase 3 (`sortant/`) — cadrage métier ✅

**Principe** : on envoie **le même type d’extrait** que celui qu’on attend en `entrant/`, mais généré depuis **notre** base (`products` + `variants`).

### Ce qu’on a côté Reboul (rappel données)

| Entité | Champs utiles pour un export |
|--------|----------------------------|
| `products` | `reference`, `name`, `price`, marque, collection, actif… |
| `variants` | `sku`, `color`, `size`, `stock` |

*(Pas `orders` dans ce flux.)*

### Alignement avec le process actuel Reboul ✅

Aujourd’hui (hors SFTP) :

1. **Feuille de stock** (souvent issue de l’AS400 / magasin) : colonnes type **Marque, Genre, Référence, Stock**
2. **`./rcli import feuille-to-csv`** → CSV import BDD (`name;reference;brand;category;collection;stock;price`)
3. **Admin** → import upsert (`reboul-import.service`) : ref/sku existant → **stock mis à jour**

La **Phase 2 AS400** = automatiser l’étape 1–3 : le CSV horaire dans `entrant/` remplace la feuille + import manuel.

La **Phase 3** = envoyer à l’AS400 un fichier du **même esprit** (extrait produit/stock), généré depuis notre BDD.

### Granularité — décision 1 ✅

| Choix | Décision |
|-------|----------|
| 1 ligne = quoi ? | **Comme la feuille de stock** : une ligne par **référence stock** (souvent ref + taille dans le champ Référence, ex. `L100001/V09A 29`) |
| Schéma BDD | Déjà bon : `products.reference` + `variants` (sku, stock, color, size) — l’import sait dériver taille/sku depuis la ref |

### Format cible (miroir process existant)

**Entrant (AS400 → nous)** — hypothèse proche feuille :

| Colonne feuille / AS400 | → Import Reboul |
|-------------------------|-----------------|
| Marque | `brand` |
| Genre | `category` |
| Référence | `reference` (+ déduction `size` / `sku` comme aujourd’hui) |
| Stock | `stock` |

**Sortant (nous → AS400)** — même logique en export :

| On exporte depuis la BDD | Colonne visée |

Format fichier import complet déjà supporté : `name;reference;brand;category;collection;stock;price` (+ `color;size;sku` en CSV « complet »).  
→ Voir `admin-central/.../reboul-import.service.ts` · exemple `docs/imports/import-stone-island-ss26.csv`

#### Complet vs delta (sortant → AS400)

| Approche | Avantages | Inconvénients |
|----------|-----------|---------------|
| **Fichier complet** chaque heure | Simple côté AS400 (remplace tout) ; pas d’historique « dernier export » obligatoire | Gros fichier, plus de calcul chez eux si tout est retraité |
| **Delta** (lignes modifiées seulement) | Moins de données, moins de calcul AS400, plus « intelligent » | Reboul doit **tracker** ce qui a changé (stock, prix, actif…) ; gérer **suppressions** (produit désactivé) ; 1er envoi = souvent **complet** |

**Côté Reboul (entrant)** : si l’AS400 envoie un **complet**, pas grave — notre import fait déjà **upsert** (seules les refs touchées bougent en BDD).

**Côté sortant (Reboul → AS400)** : **décision tenue** = export **delta** (lignes modifiées). À **confirmer** avec l’expert que leur import AS400 gère bien les mises à jour partielles (+ suppressions).

Pistes techniques Phase 3 *(plus tard)* :

- Comparer stock / prix / `active` au dernier export (table ou fichier « état précédent »)
- Colonnes `change_type` : `update` | `delete` (pour les refs retirées du catalogue actif)
- **Filet de sécurité** : 1× par semaine un **complet** pour resynchroniser

#### Lignes modifiées « colorées »

Un CSV ne colore pas → en **delta**, toutes les lignes du fichier **sont** des modifs (équivalent métier au surlignage). Sinon colonne `modified=1` dans un complet.

## Risques

| Risque | Mitigation |
|--------|-----------|
| Fichier stocks malformé → crash parser | Validation + rollback + alerte |
| AS400 ne dépose plus de fichier | Alerte après 2h sans fichier |
| Accès non autorisé au SFTP | Chroot jail + IP whitelist + fail2ban |
| Désync stock | Réconciliation hebdo + alerte divergence > seuil |
